# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

A single Next.js 16 application using React 19, TypeScript, Tailwind CSS 4, and shadcn/ui with Base UI primitives. The repository uses npm and deploys as one application.

## Users

The public website serves two audiences through progressive disclosure:

- Members of the public, policymakers, service leaders, and subject-matter experts who want to know what the draft strategy proposed for a public service, what data actually exists behind it, and what a working example does and does not show.
- Public-sector delivery teams, civic technologists, and software engineers who want a starting point they can fork: a typed playbook definition, a readable synthetic dataset, and a demo whose method is visible in the source.

## Product Purpose

The project is an open-source starting point for anyone who wants to engage with Northern Ireland's draft AI strategy — particularly the example projects the draft calls out. Those examples are this site's playbooks.

Every playbook shows four things, in this order:

- **A — the example the strategy draft gave.** What the draft proposed for this service, in plain English, with a link to the draft itself.
- **B — the data sources investigated.** The real published sources appropriate to that example: who publishes them, what they cover, how open they are, and why they fit.
- **C — a synthetic dataset.** A small dataset generated by AI and shaped by what the real sources publish, so anyone can try the idea without an API key, an account, or a data-sharing agreement. Where a synthetic stand-in would not be responsible, the playbook says so plainly and says what a contributor would need instead.
- **D — a demo.** A working example built on A, B, and C. Where none has been built, the playbook says what a demo would show and that nobody has built it yet.

Each playbook closes with one short caveats block: the honest limits of what is on the page.

The first release establishes that structure across the whole catalogue and proves it end to end with one demo: Policy Evidence Workbench.

## Positioning

Most government AI inventories list use cases without showing the data behind them or letting anyone try the idea. Most AI demo galleries show an interaction without the public-service context, the real sources, or an honest statement of limits. This project joins those layers in one place: the proposal, the data that exists, a dataset anyone can use, and — where one has been built — a demo you can read the method of.

The project is independent. It does not imply government endorsement and must not imitate an official government service.

## Operating Context

A visitor browses or searches the catalogue, opens a playbook, and reads the four sections and the caveats. Where a demo exists, they can open it and see the same conclusion recomputed from the committed dataset in front of them.

Contributors work inside this one Next.js repository through four routes: improve a playbook's plain-English content, add or verify a data source, contribute a synthetic dataset, or build a demo for a playbook that already has a dataset. A playbook is a complete, useful contribution long before it has a demo.

## Capabilities and Constraints

- The project is one Next.js application with one package manifest and one deployment unit.
- Every playbook uses the same typed schema and answers all four sections — strategy example, data sources, synthetic dataset, demo — plus caveats.
- The MVP ships A, B, and C for all seventeen playbooks, with an honest `not-responsible` answer to C where a synthetic stand-in would be irresponsible, and exactly one D: Policy Evidence Workbench.
- No runtime model calls and no API keys. A demo computes its result from committed data on every render, so it needs no credentials and can be read in the source.
- Synthetic data is honestly labelled everywhere it appears, and is never presented as official data or as evidence that a system works operationally.
- No person-level data is committed. No personal names, personal local paths, secrets, credentials, private endpoints, or sensitive records in any tracked file.
- Data pipelines, live departmental integrations, logins, databases, and uploads are outside the project.

## Evidence on Hand

The founding source is Northern Ireland's 2026 Artificial Intelligence Strategy consultation draft, particularly the example public-service projects it calls out and its recommendation to create a public-sector AI project repository.

Each playbook records the real published sources it investigated, with links. The project has no users, testimonials, deployments, measured time savings, or operational outcomes, and future work must not invent them.

## Product Principles

1. **Answer the four questions.** Every playbook says what the draft proposed, what data exists, what the synthetic dataset is, and what a demo does — or plainly that there is no demo yet.
2. **Say what is missing.** A missing dataset, a restricted source, or an unbuilt demo is stated in words, not implied by an empty space or a hopeful label.
3. **Synthetic but honest.** Synthetic data makes an idea safe and free to try. It is never a real case, a real person, an official dataset, or evidence of operational effectiveness.
4. **No key, no account, no agreement.** Anyone can validate an idea from a clean checkout. That is the point of C, and it is why no demo calls a model.
5. **One pattern, many playbooks.** The same structure across every domain makes playbooks comparable and contributions maintainable.

## Accessibility & Inclusion

The presentation layer is for everyone. Content uses plain English, avoids unexplained AI and government jargon, works across keyboard and assistive-technology navigation, does not rely on colour alone, and keeps the whole explanation — including the demo's dataset and findings — readable without client JavaScript.
