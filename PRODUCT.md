# Product

## Platform

web

## Stack

A single Next.js 16 application using React 19, TypeScript, Tailwind CSS 4, and shadcn/ui with Base UI primitives. The repository uses npm and deploys as one application.

## Users

The public website serves builders in Northern Ireland's technology, public-service, civic-tech, research, and delivery ecosystem. Public and policy readers remain supported through plain English and visible evidence.

Builders are likely to use an AI coding agent, clone the repository, and adapt an open-source reference rather than follow a prescribed product brief.

## Product Purpose

This project accelerates builders exploring the public-service opportunities named in Northern Ireland's draft AI strategy. Each playbook supplies the strategy opportunity, the published sources already investigated, safe synthetic starter data where responsible, honest constraints, and a repository-scoped domain build partner for a coding agent.

The website helps a builder choose and inspect an opportunity. The cloned repository helps them decide what—if anything—is worth prototyping. The project does not recommend a product, claim that AI is required, or provide a deployed service.

## Positioning

The product is an independent, annotated open-source field manual rather than a procurement catalogue, model leaderboard, government marketing site, or prototype gallery. It does not imply government endorsement or imitate an official government service.

Its primary proposition is: **17 public-service opportunities. The desk research is already done.** Builders start with published sources, safe sample data, and a domain build partner that ships with the repository.

## Operating Context

A builder opens the Opportunity Atlas, chooses an opportunity, inspects the evidence and starter data, clones the repository, invokes the matching domain build partner, and decides whether there is anything worth prototyping.

Contributors improve opportunity explanations, source research, synthetic datasets, domain briefs, and repository-scoped build-partner skills. A playbook is complete when its strategy opportunity, investigated sources, synthetic-data answer, titled caveats, and derived build partner are complete.

## Capabilities and Constraints

- The project is one Next.js application with one package manifest and one deployment unit.
- Every playbook uses one typed schema: a strategy opportunity, at least one investigated published source, a synthetic-data answer or responsible refusal, titled caveats, and a derived, validated repository skill.
- Synthetic data is AI-authored, visibly labelled **Synthetic working data**, and never presented as official data, a real case, or evidence of operational effectiveness.
- Published evidence is visibly labelled **Real published source**.
- No runtime model calls, API keys, accounts, databases, uploads, production data pipelines, or private departmental integrations.
- No person-level data is committed. No personal names, personal local paths, secrets, credentials, private endpoints, or sensitive records belong in tracked files.
- JavaScript may power meaningful exploration. WCAG 2.2 AA, keyboard operation, visible focus, reduced motion, forced colours, and 200% zoom remain requirements.

## Evidence on Hand

The founding source is Northern Ireland's 2026 Artificial Intelligence Strategy consultation draft, particularly the public-service opportunities it names and its recommendation to create a public-sector AI project repository.

Each playbook records the published sources investigated, with links. The project has no users, testimonials, deployments, measured time savings, or operational outcomes, and future work must not invent them.

## Product Principles

1. **Builder first.** Every page moves from understanding to usable assets: sources, starter data, repository files, and build-partner instructions.
2. **Evidence before invention.** The project shows the path from strategy opportunity to published sources to synthetic working data; it does not prescribe a product or publish a fixed solution set.
3. **Synthetic but useful.** Synthetic data is safe starting material, not evidence. Its purpose, shape, preparation, and limitations are independently visible.
4. **Agent-ready by design.** Each cloned playbook carries a focused domain build partner that supplies context and boundaries without claiming professional authority.
5. **Constraints are part of the brief.** Titled caveats are conditions a responsible prototype would need to address, not footnotes or scores.

## Accessibility & Inclusion

The presentation layer is for everyone. Content uses plain English, avoids unexplained AI and government jargon, works across keyboard and assistive-technology navigation, and does not rely on colour alone. Meaningful interactive states have text and semantic equivalents, and all core content and actions remain available at 200% zoom.
